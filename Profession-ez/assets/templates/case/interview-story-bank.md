# 面试故事库

> 每个故事 = 一个面试题的"标准答案素材"。
> 不是让你背，而是让你提前把经历梳理清楚，面试时不慌、不乱、不自我矮化。
> 每个故事都用 STAR 框架写，但要加上转行人员专属的"迁移点"和"风险措辞"。

---

## 模板

### Story: ＜故事名称，比如"从零搭建AI标注系统"＞

- **适用问题类型**：（自我介绍 / 项目经历 / 你最有成就感的事 / 举例说明你的XX能力）
- **S - 情境**：（当时的背景，为什么要做这件事？—— 要短，别铺垫太多）
- **T - 任务**：（你要达成什么目标？你的角色是什么？）
- **A - 行动**：（你具体做了哪 3 步？—— 用动词开头，说你做的，不是团队做的）
- **R - 结果**：（做成了什么样？有数据给数据，没数据给定性结果）
- **可迁移到目标岗位的点**：（⭐ 转行必备——你前行业的经验怎么用到新岗位上）
- **证据/作品**：（链接 / 截图 / 文档 / 数据，有就贴，没有就去做一个）
- **匹配的岗位关键词**：（这个故事能命中 JD 里的哪些词？列 3-5 个）
- **可能被追问的点**：（面试官大概率会深挖的 2-3 个问题，提前想好答案）
- **风险措辞（绝对不能说）**：
  - 例："我也不太懂，就是跟着做"
  - 例："也就待了一周，主要是学习参考"
- **改进版回答（1分钟版）**：
  （写一段可以直接说的话，60-90 字，结论先行）
- **改进版回答（3分钟版）**：
  （更详细的版本，有背景、有细节、有数据，200-300 字）

---

## 示例（种子案例）

### Story: 搭建 AI 标注系统

- **适用问题类型**：项目经历 / 你会用 AI 做什么 / 举例说明你的学习能力
- **S - 情境**：转行学习期间，发现数据标注是很多 AI 项目的基础环节，但市面上工具要么贵要么复杂
- **T - 任务**：用现有 AI 工具搭一个能用的标注小系统，证明自己能把 AI 落地到具体场景
- **A - 行动**：
  1. 调研标注场景，确定要支持文本分类和实体抽取两种任务
  2. 用 Prompt + 大模型 API 搭核心标注逻辑，设计输出格式
  3. 做了简单的结果校验，对比人工标注准确率
- **R - 结果**：完成了一个可运行的标注流程，文本分类准确率约 85%，能节省一半人工标注时间
- **可迁移到目标岗位的点**：
  - AI 工具落地能力（不是只会聊天，是真能用 AI 解决具体问题）
  - 工程化思维（从需求到落地的全链路思考）
  - 数据意识（知道怎么衡量效果、怎么迭代）
- **证据/作品**：项目文档 + 标注样例
- **匹配的岗位关键词**：AI落地 / Prompt / 数据处理 / 流程优化 / 工具搭建
- **可能被追问的点**：
  - "准确率怎么测的？" → 提前准备好测试方法和数据
  - "遇到最大的困难是什么？" → 说一个真实困难+你怎么解决的
- **风险措辞（绝对不能说）**：
  - "就是跟着教程做的"
  - "挺简单的，没什么技术含量"
- **改进版回答（1分钟版）**：
  我之前用大模型搭过一个 AI 标注小系统，支持文本分类和实体抽取两种任务，准确率大概 85%，能省一半人工标注时间。这个过程让我对 AI 落地的全链路有了体感，从需求分析到效果验证都走了一遍。
- **改进版回答（3分钟版）**：
  （根据需要展开，说清楚背景、你为什么选这个方向、具体怎么做的、遇到什么坑、怎么解决的、最后结果怎么样）

---

## 使用说明

1. **每个方向至少准备 3 个故事**：一个技术/项目类、一个软技能/协作类、一个学习/成长类
2. **故事不用高大上**：小项目、课程作业、自学作品都可以，关键是你真做过、能说清楚
3. **定期更新**：每次面试后把答得好的和答得差的都更新进去
4. **和错题本配合用**：错题本记录"哪里说错了"，故事库记录"应该怎么说"
