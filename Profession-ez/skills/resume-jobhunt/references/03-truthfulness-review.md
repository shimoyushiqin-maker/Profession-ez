# 03 · 真实性审核

## 目的

帮用户"把真的写好"，绝不帮用户"编假的"。编造的简历过不了背调，也过不了面试追问，一旦穿帮，用户损失更大。

## 审核规则

逐条 bullet 检查：

1. **有没有真实经历支撑？** 没有 → 删掉或标 `needs_proof`
2. **有没有交付物/数据佐证？** 没有 → 提醒用户补充，或弱化表述
3. **职级/角色有没有夸大？** "参与"不能写成"主导"，"协助"不能写成"负责"
4. **时间线有没有问题？** 空窗期、短期经历，准备好面试怎么解释（不撒谎）

## needs_proof 处理

缺证据的内容标 `needs_proof`，并告诉用户：
- 这条要么补证据，要么改弱，要么删掉
- 例：`"独立负责大促活动" [needs_proof：需具体数据，否则改为"参与大促活动执行"]`

## 短期经历 / 空窗期话术

- 短期试岗（如一周）：可以不写进简历，面试被问如实说"试岗后发现方向不匹配"，不撒谎不隐瞒
- 空窗期：说"在系统学习 XX、做了 XX 项目"，把空窗变成学习期

## 铁律

- 绝不主动建议用户编造
- 用户想编时，说明风险（背调、面试追问穿帮），给真实的替代写法
