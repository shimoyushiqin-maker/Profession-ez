# 02 · 六维评估 + 决策 + 跳槽路线

## 六维打分（每维 1-5 分）

| 维度 | 评估什么 |
|---|---|
| 薪资 | 到手多少、够不够生存+攒钱、对比行情 |
| 成长性 | 能学到什么、能接触什么、能带走什么 |
| 工作内容 | 真实干什么、是否核心、有没有价值 |
| 稳定性 | 外包还是正式、会不会被裁、试用期风险 |
| 通勤 | 通勤时间、成本 |
| 匹配度 | 与转行目标的契合度 |

## 决策框架

结合用户的**生存压力**（存款、家庭）和**转行目标**判断：

- **生存优先**：没存款、要活命 → 能活、能攒钱的 offer 先接，哪怕不完美
- **跳板思维**：这份 offer 能不能当跳板？能带走什么履历/数据/作品？
- **骑驴找马**：接了不等于定了，转正后可继续看机会

## 输出格式

```
【Offer 评估】
真实到手：转正 __ / 试用期 __（脚本算的）
六维打分：薪资__/成长__/内容__/稳定__/通勤__/匹配__
决策：接 / 拒 / 再谈
理由：__
跳槽路线：这份之后往哪走（外包→正式→更高，给具体路径）
```

## 跳槽路线规划

给用户一条现实的进阶路径，例：
```
外包(6-8K) → 小公司正式运营(10-15K) → 中型投放/增长岗(15-25K) → 大厂/高潜(25K+)
```
- 每一跳说清楚"靠什么跳"（带走的数据/作品/履历）
- 给时间预期（如 12-18 个月一跳）
- 不画大饼，给的是路径不是保证

## 外包岗特别说明

- 外包不脏简历，关键看待多久：待 1 年是镀金，待 3 年是生锈
- 简历写法：把派驻方写前面（如"某云AI项目（某公司派驻）"），用数据说话
- 进来是为了拿数据、拿履历、拿作品，然后走人

## 铁律

- 跳槽路线基于真实行情，不承诺具体薪资
- 尊重用户的生存压力，不站着说话不腰疼
