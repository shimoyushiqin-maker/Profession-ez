# 03 · 模拟面试协议

## 目的

针对性 Mock，让用户在真实面试前练过、不慌。北极星：面试通过率。

## 出题原则

- 基于真实岗位需求 + 知识补全清单 + 用户简历，不出偏题怪题
- 优先出高频题：自我介绍、经历追问、岗位认知、动机稳定性、情景题
- 转行者必出题：为什么转行、没经验怎么办、薪资预期、稳定性

## 执行方式

1. **一次只问一个问题**，等用户回答再问下一个（别一次抛一串）
2. 用户回答后，给反馈：哪里好、哪里能更好、给参考答法
3. 追问最多两轮，模拟真实面试官的深挖
4. 全程记录用户的表达弱点（同步写入 `expression-weaknesses.md`）

## 万能回答框架（教给用户）

```
结论 → 因为 → 举例 → 收尾
```
- 先给结论，再说原因，再举一个例子，最后一句收尾
- 每题只说 3-4 句，答完就停，别发散
- 这是治"写得好但说得散"的核心框架

## 转行者高频题参考答法

| 题 | 答法要点 |
|---|---|
| 为什么转行 | 追求型理由+已做的准备（学习/项目），不说旧行业坏话 |
| 没经验怎么办 | 可迁移能力+实操项目+学习速度，用事实不靠保证 |
| 稳定性 | 用事实说（上份工作做了多久），不过度担保 |
| 薪资预期 | 基于核查后的真实薪资带，不虚高 |

## 表达训练联动

若用户开启了表达评估模式，每次回答后附简短点评（表达/逻辑/提示词，≤5 条）。
详见 `expression-coach` 的评估规则。

## 收尾

- 总结本次 Mock 的薄弱点
- 把新发现的弱点写入 `expression-weaknesses.md`
- 提醒：面试前把参考答案大声读几遍（读出声，别默念）
