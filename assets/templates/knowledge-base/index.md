## 知识库分层架构

```
知识库
├── 🧩 通用方法论层（所有转行方向通用）
│   ├── 转行方法论（决策方法、可行性评估、JD调研）
│   ├── 简历优化方法、面试备战方法、表达训练方法
│   ├── 工具脚本（薪资计算器、JD关键词分析器等）
│   └── 错题本（所有方向通用的踩坑经验）
│
├── 💼 岗位方向层（每个岗位方向一个子目录）
│   ├── ai-operations/        # AI运营方向（目前最完善）
│   │   ├── 入门知识
│   │   ├── 学习计划
│   │   ├── 项目库
│   │   ├── 面试题库
│   │   └── 行业数据
│   ├── fde-solution/         # FDE/解决方案方向
│   ├── ai-product-manager/   # AI产品经理方向
│   ├── growth-marketing/     # 增长/投放运营方向
│   └── ...（更多方向按需扩展）
│
└── 🔧 技术栈层（可复用的硬技能，多个岗位都会用到）
    ├── excel-data/           # Excel/数据分析
    ├── python-basics/        # Python入门
    ├── sql-basics/           # SQL入门
    ├── ai-tools/             # AI工具使用（Prompt/生图/视频）
    └── ...（更多技术栈按需扩展）
```

**设计原则**：
- 通用方法论只写一次，所有方向复用
- 每个岗位方向独立成块，互不干扰
- 技术栈是公共资源，多个方向都可以引用
- AI运营先做厚做样板，其他方向按需扩展
- 扩展新方向时，方法论和技术栈直接复用，只补行业和岗位知识

## 飞轮运转：知识库怎么越用越厚

```
用户使用 skill → 产生新案例和 badcase
        ↓
脱敏后沉淀：
  • 新行业的能力迁移经验 → 通用方法论层
  • 新岗位的知识和面试题 → 对应岗位方向层
  • 新技术栈的学习路径 → 技术栈层
  • 踩坑经验 → 错题本
        ↓
下一个用户来时，知识库更厚 → 输出质量更高
        ↓
（飞轮加速）
```

**每次服务完一个用户，必须检查**：
- 有没有新的知识可以补充进知识库？
- 有没有踩的坑可以记进错题本？
- 有没有新的行业/岗位方向可以扩展？
- 有没有 badcase 需要修复 skill 规则？

> 沉淀不是"有时间再做"，是 skill 流程的最后一步，必须做。
