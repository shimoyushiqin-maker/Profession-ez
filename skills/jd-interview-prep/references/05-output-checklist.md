# JD备战 · 输出自检清单

> 每次输出面试备战内容前，逐条核对。不通过的项目，必须回去改，改完再输出。

---

## 一、JD 调研基础

- [ ] **目标公司的 JD 读了吗？**：针对具体面试的，有没有读对方公司的 JD？
- [ ] **行业 JD 调研有吗？**：同岗位 15+ JD 的高频题来源有吗？
- [ ] **公司背景查了吗？**：公司做什么的、主营业务、产品、规模、融资情况？
- [ ] **岗位是做什么的**：这个岗位具体干什么、团队多大、向谁汇报？

---

## 二、面试题质量检查

- [ ] **覆盖三类题**：行业认知类 / 专业能力类 / 项目经验类，都覆盖了吗？
- [ ] **来自真实 JD**：面试题是从 JD 和真实面经里提炼的，不是凭空编的吗？
- [ ] **有参考答案**：每道题都有参考回答思路吗？（不是标准答案，是思路框架）
- [ ] **结合用户背景**：
  - [ ] 参考答案里用到了用户的真实经历吗？
  - [ ] 突出了用户的差异化优势吗？
  - [ ] 避开了用户的薄弱点吗？
- [ ] **有追问预判**：重点问题有没有预判面试官可能的追问？

---

## 三、自我介绍检查

- [ ] **有 1 分钟版**：精简、抓重点、钩子结尾
- [ ] **有 3 分钟版**：更详细，有经历有数据
- [ ] **突出差异化**：不是"我叫XX我想转行"，而是"我有XX背景+XX能力，适合这个岗位因为XX"
- [ ] **结尾引导**：自我介绍最后有引导面试官问你擅长的方向吗？
- [ ] **不自我矮化**：没有主动说"我是转行的没经验""我也就学了一点"这类话吗？

---

## 四、项目介绍检查

- [ ] **每个项目都有 STAR 话术**：情况/任务/行动/结果 都有吗？
- [ ] **3 分钟内能讲完**：不会太长太啰嗦吗？
- [ ] **重点突出"我"做了什么**：不是"我们做了什么"，是"我做了什么、我贡献了什么"
- [ ] **有数据支撑**：结果部分有量化数据吗？
- [ ] **和岗位匹配**：项目介绍里的关键词和能力，是 JD 里要的吗？

---

## 五、模拟面试检查

- [ ] **是真模拟吗**：不是念答案，是一问一答的真实模拟
- [ ] **有计时**：回答时长合理吗？（每题 1-3 分钟）
- [ ] **有反馈**：模拟完有点评吗？
  - [ ] 答得好的地方
  - [ ] 答得不好的地方
  - [ ] 具体怎么改
- [ ] **表达问题记录**：发现的表达弱点，同步到 expression-weaknesses.md 了吗？

---

## 六、真实性检查

- [ ] **面经是真实的吗**：引用的面经是真实平台的，不是编的吗？
- [ ] **公司信息准确吗**：公司业务、产品、规模的信息是准确的吗？有来源吗？
- [ ] **没有编造答案**：参考答案是基于用户真实经历优化的，不是凭空编的吗？
- [ ] **不教用户撒谎**：有没有教用户编造经历或数据？（绝对不行）

---

## 七、数据归档检查

- [ ] **面试题库更新了吗？**：新的面试题补充进 knowledge-base 了吗？
- [ ] **interview-log.md 更新了吗**：模拟面试记录写了吗？
- [ ] **mistake-book.md 更新了吗**：答错的题、踩的坑，记进错题本了吗？
- [ ] **expression-weaknesses.md 更新了吗**：发现的表达弱点记下来了吗？

---

## 红线

- ❌ 绝对不能教用户编造经历、数据、学历
- ❌ 不能教用户"面经背下来就行"——要教思路和方法，不是教背诵
- ❌ 不能保证"这样回答一定过"——只能说"这样回答更有条理、更有说服力"
