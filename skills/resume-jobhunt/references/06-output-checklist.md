# 简历优化 · 输出自检清单

> 每次输出优化后的简历前，逐条核对。不通过的项目，必须回去改，改完再输出。
> 这是质量保障的第一道防线。

---

## 一、JD 匹配检查

- [ ] **JD 拆解做了吗？**：目标岗位的 JD 拆解成关键词、能力要求、岗位职责、隐性信号了吗？
- [ ] **关键词覆盖**：JD 里的前 10 个高频关键词，简历里至少出现了 8 个吗？
- [ ] **能力一一对应**：JD 里的每一项硬技能要求，简历里都有对应的经历证明吗？
- [ ] **职责方向对齐**：简历里的经历描述，和 JD 的岗位职责方向一致吗？
- [ ] **关键词位置对**：关键词出现在技能栏、经历 bullet、个人简介等关键位置了吗？
- [ ] **没有堆砌**：关键词是自然融入的，不是报菜名式的堆砌吗？

---

## 二、经历翻译质量检查

- [ ] **每段经历都翻译了吗？**：旧行业的经历都翻译成新行业的语言了吗？
- [ ] **是翻译不是编造**：
  - [ ] 能力是真实的，只是换了说法
  - [ ] 没做过的事没有写
  - [ ] 没有凭空添加经历
- [ ] **用了强动词开头**：每条 bullet 都是动作动词开头（负责/主导/搭建/优化/推动/实现…）吗？
- [ ] **有数据支撑**：
  - [ ] 每条经历都有量化结果吗？
  - [ ] 数字合理吗？（不是瞎编的离谱数字）
  - [ ] 没有精确数据的，用了范围值或估算值吗？
- [ ] **STAR 结构**：重要经历的 bullet 符合"动作+内容+方法+结果"吗？
- [ ] **突出可迁移能力**：旧经验里的通用能力（沟通/协调/数据分析/项目管理…）都凸显出来了吗？

---

## 三、简历结构和格式检查

- [ ] **一页纸原则**：转行初期简历控制在 1 页了吗？
- [ ] **信息密度高**：没有废话，每一句话都在证明"我适合这个岗位"吗？
- [ ] **结构清晰**：
  - [ ] 个人信息（姓名/联系方式/求职意向）在顶部
  - [ ] 工作经历按时间倒序
  - [ ] 项目经历独立成块
  - [ ] 技能栏分类清晰
- [ ] **ATS 友好**：
  - [ ] 用的是标准字体吗？
  - [ ] 没有用表格/文本框/图片里的文字吗？
  - [ ] 章节标题是标准的吗（工作经历/教育背景/项目经历/技能）？
- [ ] **没有无关内容**：和目标岗位无关的经历、兴趣爱好、个人照片（除非要求），都删了吗？

---

## 四、项目经历检查

- [ ] **每个项目都有价值吗？**：都能证明目标岗位需要的能力吗？
- [ ] **项目描述完整吗？**：
  - [ ] 做了什么（背景+目标）
  - [ ] 怎么做的（方法+工具）
  - [ ] 结果怎么样（数据+成果）
- [ ] **有技术含量吗？**：不是"参与了一下"，而是有具体的贡献和产出
- [ ] **数据真实合理**：项目里的数字合理吗？能经得起追问吗？
- [ ] **和旧行业结合**：有没有利用用户旧行业背景的差异化项目？

---

## 五、真实性审查（红线）

> 以下任何一项不通过，立刻回炉重造，这是底线。

- [ ] **没有编造经历**：所有工作经历都是真实的
- [ ] **没有编造数据**：数据都是真实的或合理估算的，不是凭空瞎编
- [ ] **没有编造学历/证书**：学历、证书都是真实的
- [ ] **没有编造公司/职位**：没有夸大职位或虚构公司
- [ ] **翻译没有失真**：只是换了说法，没有无中生有
- [ ] **没有夸大到离谱**：比如一个实习生写成"项目负责人"

> ⚠️ 翻译 = 换个说法突出匹配点，不等于编造。
> 可以优化措辞，但不能改变事实。可以合理估算数据，但不能凭空捏造。

---

## 六、投递适配检查

- [ ] **有通用版吗？**：有一份覆盖 80% 场景的通用简历吗？
- [ ] **有定向版吗？**：
  - [ ] 内容运营版 / FDE 版 / 增长运营版……至少 2-3 个定向版本
  - [ ] 每个版本的侧重点不同吗？
- [ ] **微调方法告诉用户了吗？**：用户知道投具体公司时怎么根据 JD 微调吗？
- [ ] **投递策略说了吗？**：
  - [ ] 优先投什么类型的公司
  - [ ] 投递渠道有哪些
  - [ ] 投递节奏怎么安排

---

## 七、数据归档检查

- [ ] **优化后的简历存档了吗？**：放在案例文件夹里了吗？
- [ ] **experience-assets.md 更新了吗？**：翻译后的经历资产库更新了吗？
- [ ] **application-tracker.csv 创建了吗？**：投递跟踪表建好了吗？
- [ ] **JD 调研结果用了吗？**：简历优化是基于 JD 调研结果的吗？

---

## 检查不通过怎么办

1. 缺什么补什么，不要硬输出
2. 真实性问题（编造）是红线，绝对不能碰
3. 拿不准的就问用户确认，不要靠猜
4. 宁可慢一点，也不要输出有问题的简历——坏简历不如没简历
