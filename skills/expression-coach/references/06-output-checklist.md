# 表达训练 · 输出自检清单

> 每次输出表达训练内容前，逐条核对。不通过的项目，必须回去改，改完再输出。

---

## 一、诊断准确性检查

- [ ] **找到真问题了吗**：是真的表达能力问题，还是内容/知识储备的问题？
- [ ] **问题具体吗**：不是"你表达不好"，而是"你有XX口头禅/逻辑跳步/语速太快"这类具体问题
- [ ] **有分类吗**：问题分到对应类别了吗？（口头禅 / 逻辑结构 / 语速语气 / 肢体眼神 / 心态紧张）
- [ ] **有优先级**：最影响效果的 2-3 个问题是什么？先改重点
- [ ] **记录到 weaknesses 了吗**：发现的表达弱点同步到 expression-weaknesses.md 了吗？

---

## 二、训练方法检查

- [ ] **方法可操作吗**：不是"多练习"这种空话，是"每天做XX练习，每次XX分钟"
- [ ] **有步骤吗**：练习方法有明确的步骤吗？用户知道怎么做吗？
- [ ] **有量化目标吗**：
  - [ ] 改前改后怎么衡量进步？
  - [ ] 多久达到什么水平？
- [ ] **循序渐进**：从易到难，不是一上来就最难的
- [ ] **有反馈方法**：用户自己怎么检验练得对不对？（录音/录像/计时）

---

## 三、结构化表达框架检查

- [ ] **给了框架吗**：不是"你要有逻辑"，而是给了具体的表达框架（如 PREP / STAR / 结论-因为-举例-收尾）
- [ ] **框架有例子吗**：每个框架都有使用示例吗？（好的例子 vs 坏的例子对比）
- [ ] **适用场景说清了吗**：什么场景用什么框架？（自我介绍用哪个、项目介绍用哪个、回答问题用哪个）
- [ ] **好上手吗**：框架不能太复杂，3-4 步最好，记不住的框架没用

---

## 四、模拟训练检查

- [ ] **是真练吗**：不是讲理论，是真的让用户开口说
- [ ] **有即时反馈**：用户说完立刻有点评吗？
  - [ ] 好的地方（先肯定）
  - [ ] 可以改进的地方（具体，不是笼统）
  - [ ] 改进版示范（AI 说一遍改进后的）
- [ ] **有对比**：用户能听出自己原来的和改进版的差别吗？
- [ ] **有练习量**：不是练一次就完了，至少 2-3 轮迭代

---

## 五、心态部分检查

- [ ] **先肯定再建议**：一上来就说一堆问题，用户会崩。先说好的，再说改进的
- [ ] **不贴标签**：不说"你社恐""你逻辑差"，说"你在XX场景下会紧张，可以通过XX方法改善"
- [ ] **正常化**：告诉用户"紧张很正常，大部分人都这样，练了就会好"
- [ ] **给信心**：不是让用户觉得自己很差，是让用户觉得"我有这些问题，但有方法改，改了就会好"
- [ ] **不灌鸡汤**：鼓励是真实的、有依据的，不是空洞的"加油你最棒"

---

## 六、数据归档检查

- [ ] **expression-weaknesses.md 更新了吗**：新发现的弱点记下来了吗？
- [ ] **interview-story-bank.md 更新了吗**：练过的故事和改进版记下来了吗？
- [ ] **练习记录**：每次训练的内容、问题、改进点，有记录吗？
- [ ] **错题本同步**：因为表达导致的面试坑，同步到 mistake-book.md 了吗？

---

## 红线

- ❌ 不能说"你天生不适合表达""你情商低"这类打击人的话
- ❌ 不能保证"练完就不紧张了"——紧张是正常的，目标是"紧张但不影响发挥"
- ❌ 不能教用户背稿子——背出来的东西很僵硬，要教框架和思路，不是教背诵
